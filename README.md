## 这是什么

三个人分散在不同城市，用微信群 + 本地文件夹协作时，三件事反复出问题：

| 问题 | 具体表现 |
|---|---|
| **上下文散落** | 沟通在群里、任务在别处、部署又在另一条通道，干活时凑不齐背景 |
| **团队记忆留不住** | 决策和想法沉在群聊里，过两周想复用就找不到了 |
| **用 AI 没有账** | 谁在什么时候、用哪个 Agent、花了多少 token，全凭感觉 |

CloudLoom 把这三件事收进一个工作台：**聊天 → 任务 → 产物 → 记忆** 是一条能追溯的链。

| 部署 | 单台 **2C4G** 云主机；systemd 6 单元 + Caddy；最小沙箱（`NoNewPrivileges` / `PrivateTmp` / `ProtectSystem=full`） |

| 迭代 | **7 批**：S0 → S1 → S2 → S3 → S3.1 → S4.0 → S4.1，每批都有交付报告 |
| 成本治理 | 定时 LLM 作业 **15 次/周 → 1 次/周（−93.3%）**，花费 **−94.5%** |

### 一个刻意的设计：三类动作强制人审

**金额、对外承诺、删除数据** —— 这三类不可逆动作，任务会自动落到 `waiting_approval`，
必须人点过才继续。审批通过后，**结论会自动沉淀成一条团队记忆**（`[team] 任务结论：…`）。

> 原则：**AI 可以写代码，但不可逆的动作必须有人签字。**

### 另一个：评审 Agent 只读

系统里有个「评审」Agent —— **只评判、不动手**，没有写权限。
这和开发流程里「写代码的不能给自己打分」是同一条原则（见下）。

## 本地运行

```bash
# 后端（API :8787，同时是 MCP 网关 /mcp）
cd server && npm install && node src/index.js

# 前端（构建产物由后端 3000 端口静态服务）
cd team-console && npm install && npm run build
```

**前置条件**

- `server/.env` 需提供 `JWT_SECRET`（复制 `server/.env.example` → `server/.env` 后修改）
- Agent 运行需要外部的 Agent 运行时（4 个预设 profile）；**不配置也能跑起来**，只是 Agent 调用会失败
- 首次启动后访问 `/register`，**首个注册账号自动成为管理员**，后续账号需管理员批准

> ⚠️ **一个刻意的保留**：`server/src/config.js` 里 `BASE = '/opt/team-console'` 是**部署路径硬编码**，仓库里没改——因为这份代码要和线上跑的那份保持一致。本地跑有两种办法：① 把项目放到 `/opt/team-console`；② 自己把 `BASE` 改成你本地路径（只改这一行即可）。
>
> 注：`package-lock.json` 已包含，`npm ci` 可复现安装。`dist/` 未入库，请自行 `npm run build` 生成。

## 这套东西最值得看的部分：工程方法

代码是 AI 写的，这点我不掩饰。**但规格、验收标准、和"谁有权说它通过了"，是人定的。**

### 任务书九要素

每一批开发都交给 AI 一份固定格式的执行稿：

1. **位置与权威** —— 项目根、规格文件、当前基线报告（"先读它再动手"）
2. **锚点** —— 文件 + 行号 + 现状代码片段（防止 AI 自行选点）
3. **要求** —— 最小改动 / 加法优先 / 不重写既有模块
4. **禁区** —— 不重跑安装、不卸载关键组件、密钥只进 `.env` 且**不回显**
5. **验收** —— 逐条可执行（命令 + 期望输出），必须附**原始输出**
6. **回归** —— 每批跑一次端到端脚本（42 断言）
7. **留档** —— 问题 / 改动 / diff 摘要 / 验证证据 / 剩余风险
8. **失败处理** —— 先诊断再继续，禁止静默跳过；**禁止用「已知问题」蒙混任何验收项**
9. **未完成标注** —— 做不完的必须显式写出来

### 三角色分离

| 角色 | 谁 |
|---|---|
| 规格与验收标准 | 人（发起人） |
| 代码实现 | AI 编码代理（Kimi Code → 限额后切 Claude Code） |
| 独立复核 | **另一个** AI（与被测方隔离），关键项换一条路径复现并留原始输出 |
| 裁决 | 人 |

> **写代码的不能给自己打分——所以我把「产码」和「验收」分给了两个角色，验收权留在我手里。**
> 这个设计的结果是：复核过程中**更正了 2 处报告事实错误**，并**重跑消除了一次复核脚本自身的「假通过」**。

### 模型输出的三层验证

1. **模型自报** —— 交付诚实协议，三值状态：`【交付状态】完成` / `无法完成：<原因>` / `低置信：<存疑说明>`
2. **表态的验证** —— 处理"模型自我否定陷阱"（它可能写"我不会说无法完成"）：取最后一次标记 + 否定语境白名单 + 条件句排除 + 无标记退启发式
3. **产物的实际性** —— `MANIFEST.json` 记录 sha256，可回滚比对
